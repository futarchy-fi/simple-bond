# Autoloop Backlog — v0.7-for-UX roadmap (iteration 1 design output)

Generated by the iteration-1 design workflow. Sequenced: backend reliability +
capability harness first (de-risk), UX next, v0.7 contracts last (testnet-first).
Full machine copy: docs/autoloop/roadmap.json.

## Ranked backlog

- **B1** (backend, no deps) — Harden the watcher to a multi-RPC FallbackProvider (list-based RPC env), Sepolia + mainnet
  - UX: Browse list, bond detail (after B3), and notification emails keep flowing through a single-RPC outage instead of going blank/stale — the exact failure preflight.mjs:30-31 attributes to incidents I2/I3/I9/I10.
  - metric: rcaOpenGaps 10->9 (gap #1); monitor.mjs stays green through a simulated primary-RPC failure.
  - verify: Unit test (extend test/backend/readModelAndIndexer.test.js child-process pattern): inject a provider list where provider[0] throws on getLogs+getBlockNumber, assert indexChain still advances the checkpoint and writes rows from provider[1]; assert quorum=1/staticNetwork config present.
- **H1** (test/infra, no deps) — Wire a `capabilities` map into the scoreboard via a Playwright post-run JSON aggregator
  - UX: Makes 'did the user-facing journey actually work end-to-end' the loop's headline metric, so the loop optimizes for working flows over cosmetic churn (CHARTER 3).
  - metric: capabilities.{createBond,becomeJudge,challengeAndRule,concede,withdraw,drainRefunds,claimTimeout} populated in metrics.json; scoreboard.mjs:67-70 renders non-empty.
  - verify: Run `playwright test --reporter=json` against the `local` project, map passing test titles (C1/E*/D*/etc.) to flags, merge into metrics.json; assert `node scripts/scoreboard.mjs --json` shows the map non-empty; a journey marked skip/host-gated maps to absent (never true).
- **A1** (frontend, deps B1) — Consume /api/bonds freshness meta in the UI: staleness banner + threshold direct-read fallback (Browse)
  - UX: Users see 'data may be N blocks behind' instead of a silently-stale list shown as truth; past a lag threshold the page transparently falls back to a direct read. Closes RCA gap #2.
  - metric: rcaOpenGaps 9->8 (gap #2); adversarial 'did my action work / staleness disclosure' score.
  - verify: e2e (page.route('**/api/bonds*')) serves a response with meta.blocksBehindHead above threshold -> assert banner renders + direct-read fallback fires; below threshold -> assert no banner and no extra bond-enumeration RPC call.
- **B3** (frontend, deps B1) — Bond detail loads from the indexer point-read (GET /api/bonds/:id): indexer-first paint (claim + per-challenge status) with background RPC enrich for timing/metadata
  - UX: The most-shared page stops showing multi-second 'Loading bond #…' spinners and intermittent RPC errors; claim text + each challenge's content/status appear instantly from the indexer. Closes RCA gap #9.
  - metric: rcaOpenGaps 8->7 (gap #9); capability 'view-bond' p95 render time.
  - verify: e2e on the `local` project: open #view/<id> with the RPC provider throttled/stubbed, assert claim text + challenge rows render within a time budget and that NO eth_getLogs is issued on the claim-paint path (page.route intercept); timing-enrich may still call RPC.
- **A2** (frontend, deps B3) — Per-challenge status timeline: active-phase highlight + explicit 'why no action / when it changes' reason sentences
  - UX: Posters/judges/challengers always see which phase a challenge is in (concession->ruling->timeout) and, when a button is absent, a sentence saying why and when it changes — eliminating the silent dead-ends at index.html:3107-3126.
  - metric: Adversarial dispute-lifecycle rubric score; supports concede/rule/claimTimeout capability narratives.
  - verify: Pure unit test of a new phaseFor(timing,status,now)->{label,reason,activeWindow} across all 4 boundaries x all statuses asserting label+reason strings (primary); existing-style Playwright e2e with mocked timestamps asserts presence/absence of each action button + matching reason (secondary). No real-chain time-warp.
- **A3** (frontend, deps B3) — USD consistency: fix My-Bonds + risk-reward unit drift so the same bond reads identically everywhere
  - UX: The same bond no longer reads '$10' in Browse but '9.78' in My Bonds; the risk/reward card shows dollars matching the belief card above it, so users trust the numbers they stake on.
  - metric: Lint/visual-consistency check; adversarial 'clarity of stakes' score.
  - verify: e2e asserts the USD string for a known bond is identical across Browse row, My-Bonds row, and detail; off-chain unit test on the formatter with a non-1:1 rate (local MockSUSDS is pinned 1:1, so conversion is covered by the unit test, not e2e).
- **A4** (frontend, deps B3,A2) — Refunds-aware UX on bond detail: surface 'you are owed $X (N slots)' and only show the drain control when something is refundable
  - UX: Conceded/rejected challengers and post-settlement holders see a clear owed affordance instead of an always-on card that wastes gas on a no-op claimRefunds; removes a confusing dead-end.
  - metric: Capability 'drainRefunds' becomes meaningful (asserts owed shown then cleared); adversarial dead-end-reduction score.
  - verify: e2e (wallet-with-node): concede a challenge, assert detail shows 'owed $X (N slots)', drain refunds, assert the affordance disappears and balanceOf moved. Drain control still shows whenever ANY slot is refundable (permissionless), only hidden when nothing is.
- **A5** (frontend, deps B3,A2) — One-line lifecycle/role banner on bond detail derived from the existing gating flags
  - UX: Every visitor immediately understands the bond's state and their available moves in plain language instead of inferring from pendingCount/closed/settled raw fields and scattered cards.
  - metric: Adversarial orientation/clarity score; supports create/challenge/rule capability narratives.
  - verify: e2e asserts banner text for 2-3 representative (role x state) combos (poster-of-open, challenger-of-disputed, settled) matches which action cards actually render; banner clauses derive from the same isPoster/canChallenge/isJudgeOperator flags the cards use (single source of truth).
- **A6** (frontend, deps A1) — Wire the opt-in notification flow (reuse existing /api/notify backend); un-hide the bell with honest 'subscribed' copy
  - UX: Async participants subscribe to be told when their bond is challenged / their window opens / a ruling lands, so a 7d+7d dispute no longer needs manual re-checking; the dead bell becomes a real control.
  - metric: New capability 'notify-subscribe' passes; un-hides a built-but-unused backend surface.
  - verify: e2e: connect mock wallet, click Notify, sign the fixed message, POST /api/notify/register against a test API, assert 200 + /status flips to registered + bell reflects state. Copy must NOT promise delivered email until mailer is enabled (EMAIL_ENABLED=false today).
- **B2** (backend, deps B1) — Dead-letter + auto-recovery (sub-chunk + retry) for permanently-failing log windows in the indexer cursor
  - UX: A single poison block range stops silently freezing the whole read-model (watcher.mjs:142-148 currently just breaks and lag grows forever); indexing keeps advancing past recoverable windows so the list stays fresh.
  - metric: rcaOpenGaps burn-down; new health field surfaces dead-lettered-window count (alertable in monitor.mjs).
  - verify: Unit test feeds a window that fails at full chunk but succeeds when halved; assert the indexer records the dead-letter, retries with a smaller chunk, recovers, and clears it. A window that fails even at 1-block must NOT advance the checkpoint (no-skip invariant preserved).
- **B4** (test/infra, deps B1) — Freshness/health SLO: last-tick-age probe enforced in monitor.mjs
  - UX: A crashed/wedged watcher pages within minutes instead of silently serving stale 200s until users notice missing bonds — turning the lag-only check into a real liveness SLO.
  - metric: monitor gate gains a last-tick-age probe; monitor.mjs exits non-zero when the watcher is stopped with a fresh-looking checkpoint.
  - verify: Test seeds chain_heads.updated_at to an old timestamp (existing child-process+temp-DB pattern) and asserts monitor.mjs alerts; a fresh timestamp passes. Threshold is a tunable env var with margin over POLL_INTERVAL_MS. (Per-RPC error-rate split out, lower priority.)
- **C1** (contract, deps H1,B1) — v0.7: pending-cap semantics for maxChallenges (gate challenge() on pendingCount, not total-ever)
  - UX: Removes a revert-on-submit: the UI already gates challenge on pendingCount<maxChallenges (index.html:2934) while the contract gates on total-ever (SimpleBondV6.sol:266), so today the form shows then the tx reverts 'Max challenges reached'. Legitimate challengers stop being permanently locked out by spam-then-reject.
  - metric: New capability 'cap blocks only on live disputes, frees after reject'; closes the SPEC_V06.md:355 open question.
  - verify: Sepolia-first journey: set maxChallenges=2, file 2, judge rejects 1, assert a 3rd challenge succeeds; extend test/core/v6/SimpleBondV6.challenge.test.js + reuse the existing invariant harness asserting pendingCount never exceeds cap. Companion edits: relabel index.html:2472 input + close SPEC_V06 open question.
- **C2** (contract, deps C1,A4) — v0.7: per-address pull-payment credit ledger with claim() + Credited event (replaces shared claimRefunds drain)
  - UX: A challenger owed a refund sees 'You are owed $X' and clicks one button that pays ONLY their balance, replacing the shared 'Drain refunds (max N)' card that pays whoever is next in the array (SimpleBondV6.sol:440-458).
  - metric: New capability 'challenger claims own settlement refund in one tx'; lets the indexer expose a per-address claimable ledger; moves the dead-end-removal UX objective.
  - verify: Sepolia journey: settle a bond with 2 pending challengers via ruleForChallenger, assert each credited balance, each calls claim() and receives exactly challengeAmount, contract token balance nets to zero. Scripted journey is the gate; fuzz invariant sum(credits)==sum(deposits-payouts) is bonus (no fuzz harness exists yet). Companion: replace the A4 drain card with per-address claim + update surface tests (which assert claimRefunds/refundCursor strings) in lockstep.

## Risks
- FRONTEND TWIN DRIFT (highest-frequency footgun): frontend/index.html (Netlify-published + served by the e2e `local` static server at :8765) and frontend/v6/index.html (read by test/frontend/SimpleBondV6FrontendSurface.test.js) are both 3460 lines and currently DIFFER. EVERY frontend item (A1,B3,A2,A3,A4,A5,A6) must edit BOTH files or one gate passes while the other rots / the served page diverges from the tested page. Add a lint/diff guardrail that flags divergence.
- INDEXER SCHEMA IS INCOMPLETE FOR FULL DETAIL: GET /api/bonds/:id serves only {idx,challenger,status,content} per challenge (api-server.mjs:395-397) and the watcher persists only challenger/status/content (watcher.mjs:54-66). challengeHtml needs timestamp/challengeAtVersion/metadataHash/rulingMetadataHash + the timing triplet. B3 must ship as indexer-first paint (claim + status, zero eth_getLogs) + background RPC enrich for timing/metadata; do NOT let the loop claim a 'zero-RPC detail page' without first extending the backend schema (a separate, larger item). A4 (refund affordance) depends on per-challenge status which the indexer DOES serve, so it is unblocked once B3 paints from the indexer.
- CONTRACT ITEMS FORCE THE FULL TESTNET-FIRST CYCLE: C1/C2 each require Sepolia deploy + verifyDeployment gate + monitor + (only later) mainnet cutover (CHARTER 24-27). C2 also rewrites ~6 disbursement paths (push->credit) and breaks the surface tests that assert claimRefunds/refundCursor strings — those must update in lockstep or the loop self-reds. No fuzz/property harness exists today, so treat the conservation invariant as bonus, not a blocking gate.
- CAPABILITY-FLAG GAMING: H1's aggregator is the only thing that can fake-green the loop's headline metric. A skipped/host-gated test (many live-* specs test.skip on baseURL) must map to absent/false, never true; flags must be keyed to a PASSING real journey. This is the one place CHARTER's 'gaming a metric is a failure' is most exposed.
- LIVE-SEPOLIA WRITE JOURNEYS ARE BLOCKED ON OWNER FUNDING + TIME-GATING: the scored live-sepolia fixture and staging write-journey items were CUT/deferred because (a) no funded Sepolia role keys exist (owner must fund out-of-band) and (b) rule/concede/withdraw need real wall-clock waits (no evm_increaseTime on Sepolia). C1/C2 verification therefore relies on the local Hardhat journey harness (which CAN time-warp) for the gate, with a read-only Sepolia smoke check after deploy — not full live write journeys. An unattended loop cannot self-fund Sepolia.
- STALE/UNVERIFIED SEPOLIA DEPLOY RECORD: deployments/sepolia.json dates 2026-05-21; C1/C2 redeploy will refresh it, but verifyDeployment.js must confirm canonical judge profile #0 is registered on the new deploy (createBondViaUI depends on it) or the journey harness hangs at the judge-resolution step.
